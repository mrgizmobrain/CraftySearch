# Crafty Search

Fabric mod for Minecraft 26.2. The full design is in `SPEC.md`. Read it before making changes; it also records the decisions made along the way (dated "Nov 5"/"Nov 6").

## Toolchain and checks

- Java 25, Gradle 9.5.1, Loom `net.fabricmc.fabric-loom` (non-remapping, Mojang names, no mappings line, use `implementation`, not `modImplementation`).
- The JDK on PATH is 21. Run Gradle with JDK 25: `$env:JAVA_HOME="$env:USERPROFILE\.jdks\ms-25.0.4.1"; .\gradlew.bat build`.
- Git is at `C:\Program Files\Git\cmd\git.exe` (installed Nov 9; a shell opened before that doesn't have it on PATH). `run/` and `.idea/` are ignored.
- Verify with `gradlew.bat build`, then `runClient` (run it in the background and wait for "Sound engine started" in its output). The user tests features in-game themselves and reports back; give them a short test list.
- `runServer` loads the mod but stops at the EULA. Don't accept the EULA for the user.

## Code map

- Common (`src/main/java/com/craftysearch`): `ServerConfig`; `storage/` (`ContainerKind`, `ContainerKey` block-or-entity identity, `ItemKey`, `PutAwayRule`, `KeepOne` the "Leave one" rule, shared by both sides); `network/` (payloads, `ModPayloads.PROTOCOL_VERSION`, bump it on any payload change); `server/` (`StorageScanner`, `StorageSync` live data, `StorageCrafting`, `StorageTransfer` take/put-away/throw, `RemoteOpen` opening a container from the panel, `ContainerInsert`, `KeptSlots` for "Leave one"; `protection/` claim and spawn checks, one class per claim mod).
- Client (`src/client/java/com/craftysearch/client`): `memory/` (`ContainerMemory` file format v3, `ContainerRecorder`, `MemoryEntry`, which looks up a cart's current position from the client level); `live/` (`ServerMode`, `LiveStorage`, `CraftRouting`, `ServerOutbox` paced take/put-away payloads); `storage/` (`StorageIndex` totals, `SearchFilter`); `recipe/` (`RecipeStorage` recipe book counting, reach and the via-intermediates state; `CraftChains` the intermediates planner, used by both modes); `background/` (client-only container access: `BackgroundAccess` hidden menus, `BackgroundJobs` runner with queue and speed, jobs `CraftJob`/`TakeJob` (stack, one, all, counted, throw)/`PutAwayJob`/`ScanJob`, `StackScan` for stacked carts, `ContainerWatch` for containers others use, `StorageActions`, `InteractionHold`); `gui/` (panel, screens, `PanelHooks`, `PanelMouse` scroll wheel and shift-drag, `PanelSortButton`, settings pages on `SettingsScreen`: a setting is one `add(toggle(...))` or `add(choice(...))` line, labelled `craftysearch.config.<key>`, with a tooltip when `<key>.tooltip` exists in the language file); `compat/ModMenuIntegration` (Mod Menu entrypoint), `compat/ShaderPacks` (Iris API by reflection), `compat/JeiIntegration` and `compat/ReiIntegration` (panel exclusion zones); `highlight/` (`Highlights` outlines and labels, `HighlightMarkers` HUD markers, `SlotHighlights`); `mixin/`.

## Pitfalls found so far

- MC 26.2 renames: `GuiGraphics` → `GuiGraphicsExtractor`, `render*` → `extract*`, `mc.screen`/`setScreen` → `mc.gui.screen()`/`mc.gui.setScreen()`, `ResourceLocation` → `Identifier`, `ResourceKey.location()` → `identifier()`.
- Check signatures with `javap` (from JDK 25) against `~/.gradle/caches/fabric-loom/minecraftMaven/net/minecraft/minecraft-{clientonly,common}-deobf/26.2/*.jar`. Fabric API's modules are nested jars inside `fabric-api-0.161.0+26.2.jar` (`META-INF/jars`); extract them to a scratch folder to inspect. From PowerShell, pass javap flags through `$args`, not named parameters (`-p` and `-c` get eaten).
- Mixin problems only show at runtime: `build` passes even when a mixin can't apply. After adding or changing a mixin, start `runClient`. Mixins on screen and recipe-book classes only load when a container screen first opens, and `LocalPlayerMixin` only when a world is joined, so the user's in-game test is the real check for those.
- A chest boat opens its chest only for a sneaking interact (otherwise the player gets in). The server sets the player's sneak state from `ServerboundInteractPacket.usingSecondaryAction` and keeps it until the next `ServerboundPlayerInputPacket`, so after a forced sneak flag, resend `LocalPlayer.getLastSentInput()` (see `BackgroundAccess.useEntity`).
- In 26.2 `Ingredient.items()` and `Item.getDefaultMaxStackSize()` are marked deprecated. Use `item.components().getOrDefault(DataComponents.MAX_STACK_SIZE, 1)` for the stack size; `items()` has no replacement for listing an ingredient's items (vanilla's placement uses it too), so `CraftChains` suppresses the warning there.
- The main settings page is full at GUI scale 4 on a 1080p screen (the row freed Nov 7 went to "Markers" Nov 8); new settings go on a sub-page (like "Containers...", "Client-only mode..." and "Mouse...").
- Recipe book screens place themselves from the screen width (`RecipeBookComponent.init` and `updateScreenPosition`), which is how the open panel shifts the screen left (`AbstractRecipeBookScreenMixin`). Anything that changes the shift needs the screen laid out again (`screen.resize(w, h)`), deferred to a client tick, never inside a click or a screen event.
- Shader packs (Iris) draw gizmo lines with their own shaders, so "always on top" outlines are hidden by walls. Anything that must show through walls with shaders on goes on the HUD (see `HighlightMarkers`). Iris isn't in `run/mods`; the user tests shader behaviour in their own game with the built jar.
- The user wrote the settings tooltips themselves (Nov 7). Don't reword them unasked; a `\n` in a tooltip string is a line break.
- Mod Menu (`modmenu_version` in `gradle.properties`) is `clientCompileOnly` plus `clientRuntimeOnly`, non-transitive: compiled against, loaded in `runClient`, never bundled. It needs only Fabric API modules.
- Claim mods, JEI and REI are compile-only; `runClient -Pwith=jei|rei|opac|flan|cpa` adds them (and their required mods) at runtime. Modrinth's Maven lists no dependencies, and for a version number shared by several loaders it may serve another loader's jar: pin those by Modrinth version id (see `gradle.properties`). Fabric shows a blocking error window for missing dependencies, so stop that run's task if it fails.
- Static state that holds a `Level` (or anything reaching it: entities, menus, the recipe index) must be cleared on disconnect (`CraftySearchClient`'s DISCONNECT handler), or the old world stays in memory.
- `getEntitiesOfClass` can't take an interface such as `ContainerEntity` (the entity lookup needs an `Entity` subclass); query `Entity.class` with an `instanceof` predicate.
- `@Shadow` only sees fields declared in the target class itself, not inherited ones (`ClientPacketListener.minecraft` is in `ClientCommonPacketListenerImpl`). To write a `final` field, use a `@Mutable @Accessor` and don't also `@Shadow @Final` it elsewhere.
- Other mods may click containers straight through `MultiPlayerGameMode.handleContainerInput` (IPN does), past `AbstractContainerScreen.slotClicked`; `MultiPlayerGameModeMixin` is the place that sees every click. During a client-only job the player's open menu is the hidden container's, so mods that draw by `player.containerMenu` draw in the wrong places (`BackgroundJobs.screenShowsAnotherMenu`).
- Packet handler mixins: inject just after `PacketUtils.ensureRunningOnSameThread` so mod state is only touched on the client thread.
- In 26.2, `RecipeBookComponent.isMouseOver` always returns false; use its private `getXOrigin`/`getYOrigin` (see `RecipeBookComponentInvoker`).
- Don't write Java files with PowerShell `Set-Content -Encoding utf8`: PowerShell 5.1 adds a BOM and `javac` rejects it, and the editor keeps that BOM on later rewrites. Use the Write tool; if a file got a BOM, delete it and recreate it.
- Chest lid block events (type 1, the opener count) aren't one per change: the server sends the current count again every 5 ticks while a chest is open, and once more (a 0) up to 5 ticks after the last closing. Only a change of the count means something happened.
- Vanilla drops a container's cursor item if the container closes with a full inventory. Client-only jobs move items through a free inventory slot ("parking") instead of leaving them on a hidden menu's cursor.
